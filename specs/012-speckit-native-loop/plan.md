# Implementation Plan: Speckit-Native Amputation

**Branch**: `refactor/speckit-native-amputation` | **Date**: 2026-08-20 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/012-speckit-native-loop/spec.md`

## Summary

Delete every mechanism that exists because there was no speckit, in one PR, on
top of a recorded green baseline. The work is overwhelmingly **subtraction of
whole functions**, not refactoring: a structural scan shows nearly every
`program` reference lives inside a function that is deleted entire. What remains
is a small set of surgical edits at call sites, plus three behavior changes
(the brief trim, the delivery title seam, the dispatch-tool sugar).

Nothing here weakens a gate. Every brake survives untouched.

## Phase ordering (within the single PR)

The PR is one commit-series; this is the order that keeps the suite meaningful
at each step, so a mistake is caught close to its cause.

1. **Leaf deletions** — no in-repo importer: `claude_sdk.py`, `project_image.py`,
   `eval_judge.py`, `evals.py`, their prompts and tests.
2. **Trend stack** — `trend_detector.py`, `trend_signals.py`, `bookmark.py`,
   the `review_trends` tool, `service.py` wiring, `DEVCLAW_TREND_*` env docs.
3. **Program vocabulary** — the largest and most threaded. Order: whole
   functions first (`task_queue`, `state_store/core`, `tools`, `http`,
   `task_notify`), then the surgical call-site edits, then `rows.Program`,
   `models.InFlight/PollResult` program members, `program_plan.py`.
4. **Superseded singles** — `repo_brief.py`, `self_issue.py`, `merge.py`,
   `elicitation.py` + scope-grill prompts and tool.
5. **`slice_guard` PLAN.md half** — `count_milestone_flips`,
   `mega_dump_flips_sync`, `_plan_at_ref_sync`.
6. **Behavior changes** — brief trim (FR-009/FR-010), delivery title seam
   (FR-005), dispatch-tool sugar (FR-006/FR-006a). Each ships its named
   regression test.
7. **Docs + rules** — `CLAUDE.md`, `docs/`, `docs/INDEX.md` currency tags,
   delete `.claude/rules/cognition-prompts.md`.

## Complexity Tracking

| Risk | Why it exists | Mitigation |
|---|---|---|
| One ~6,400-line PR, no intermediate green commit | Owner ruling (recorded in spec) | Commit-series within the PR follows the phase order above; suite run at each phase boundary; `pre-amputation-v0.3.0` is the rollback |
| **Orphaned pending program-child rows could be claimed** | FR-001a keeps `tasks.program_id` populated in history. `list_pending_standalone` filters `program_id IS NULL` | **KEEP that filter.** Deleting it as "now-vacuous" would let a historical pending program child be claimed and launched. Named regression test required |
| An untraced MCP caller | The OpenClaw waiter is outside this repo | FR-006a keeps every dispatch name callable; only 6 genuinely program/trend/scope tools are removed |
| Test count drops below baseline | ~2,950 test lines belong to deleted mechanisms | `baseline.md` records the exception: the gate is **zero failures**, not count parity, with every removed test traceable to a removed mechanism |
| `_bootstrap` DDL edit | Creates the `programs` table on fresh DBs | Leave the DDL in place OR remove it — either is safe given FR-001a. Decision: **leave `_bootstrap` DDL untouched** so a fresh DB and the live DB have identical schema; remove only the read/write methods |

## Post-design Constitution re-check

Re-evaluated after the structural scan: **still no violations.** The
`_bootstrap` decision (leave DDL, remove accessors) was added specifically to
keep Principle IV honest — one schema shape across fresh and live databases,
with a single writer that no longer writes there at all.
